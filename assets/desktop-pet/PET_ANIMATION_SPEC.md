# 网页桌宠 SVG 动画项目规范

## 【角色锁定规则】

现有 6 张图片是唯一的角色外形依据，不重新设计角色，不替换造型，不擅自增加服装、五官、文字、Logo 或装饰。

角色对应关系：

1. Gemini：蓝紫粉色、菱形星星身体
2. GPT：深灰色方形机器人，胸前绿色结状图案
3. Grok：黑白宇航员，胸前白色闪电
4. DeepSeek：蓝色鲸鱼，右眼带搜索镜
5. Qwen：紫色圆球，头顶卷曲触角
6. Copilot：黑色机器人，背后有蓝紫橙彩色飘带

所有后续动作都必须继承参考图片中的：

* 身体比例
* 头身比例
* 五官位置
* 主体颜色
* 服装结构
* 标志性配饰
* 像素化或硬边 Q 版视觉风格

## 【动作清单】

每个角色需要支持：

`idle`、`idleLook`、`thinking`、`working`、`building`、`juggling`、`error`、`happy`、`notification`、`sweeping`、`carrying`、`yawning`、`collapsing`、`sleeping`、`waking`、`drag`、`clickLeft`、`clickRight`、`annoyed`、`double`、`roam`、`miniIdle`、`miniPeek`、`miniAlert`、`miniHappy`。

## 【角色专属动作语言】

### Gemini：

* 待机时身体悬浮，蓝紫粉光泽缓慢流动。
* 思考时依次点亮小型菱形星光。
* 工作时半透明菱形切面环绕旋转。
* 多任务时分裂成多个彩色菱形协同处理。
* 子任务时抛接蓝、紫、粉三颗星星。
* 错误时星光失衡、身体轻微扭曲后恢复。
* 成功时展开成明亮四角星并释放星屑。
* 通知时中心快速发光并出现感叹号星星。
* 睡眠时整体变暗，小星星缓慢呼吸闪烁。
* 拖动时拉成长菱形，尾部保留星光轨迹。
* 移动时小幅弹跳并短距离瞬移。

### GPT：

* 胸前绿色结是所有动作的核心视觉元素。
* 思考时绿色结逐层旋转，眼睛显示思考点。
* 工作时展开绿色全息键盘。
* 多任务时建立绿色节点网络。
* 子任务时抛接绿色数据节点。
* 错误时绿色结打乱，眼睛显示错误符号。
* 成功时绿色结完全点亮并举手庆祝。
* 整理时用刷子清扫数据方块。
* 搬运时抱着文件夹或绿色数据立方体。
* 睡眠时坐下关机，绿色灯缓慢呼吸。
* 移动时使用短小机械步伐。

### Grok：

* 整体保持低重力漂浮感。
* 思考时头盔出现扫描线，胸前闪电蓄能。
* 工作时操作悬浮控制面板。
* 多任务时召唤黑白卫星模块。
* 子任务时抛接三颗发光小行星。
* 错误时闪电短路、头盔出现静电。
* 成功时摆出英雄姿势并释放白色电弧。
* 睡眠时漂浮蜷缩。
* 唤醒时在空中翻转后恢复。
* 移动时使用月球漫步动作。

### DeepSeek：

* 鲸鱼尾巴轻摆，右眼搜索镜偶尔转动。
* 思考时搜索镜伸缩扫描并产生气泡。
* 工作时投射蓝色扫描光，鱼鳍操作水波界面。
* 多任务时生成包含任务符号的数据气泡。
* 子任务时用喷水柱托起三颗水滴球。
* 错误时搜索镜起雾并吹出失败气泡。
* 成功时跃起并喷出星形水花。
* 整理时用尾巴扫走数据泡泡。
* 搬运时背着文件数据泡泡。
* 睡眠时趴在水波上吹出规律气泡。
* 移动时小幅游动或弹跳。

### Qwen：

* 圆球身体轻轻弹动，触角缓慢摆动。
* 思考时触角卷成问号。
* 工作时触角分出光点操作文字卡片。
* 多任务时用触角堆叠方块和文档。
* 子任务时触角控制三颗紫色光球。
* 错误时触角打结，身体压扁后弹回。
* 成功时高高弹起并旋转。
* 整理时触角变成小扫帚。
* 搬运时触角卷住文件。
* 睡眠时身体变扁，触角盘成枕头。
* 移动时连续弹跳。

### Copilot：

* 黑色机器人和背后彩色飘带必须同时保留。
* 思考时飘带环绕头部形成轨道。
* 工作时双手操作代码面板，飘带协助输入。
* 多任务时飘带连接并组装代码模块。
* 子任务时飘带抛接三个代码方块。
* 错误时飘带褪色并打结。
* 成功时飘带展开成彩色翅膀。
* 整理时飘带清扫代码碎片。
* 搬运时飘带托住文件模块。
* 睡眠时飘带围成被子。
* 唤醒时飘带依次亮起并把机器人弹醒。
* 移动时小跑，飘带形成短轨迹。

未单独描述的动作，应在保持角色特征的前提下，根据动作名称自然设计。

## 【SVG技术规范】

1. 最终成果必须是原生可编辑 SVG，不是把 PNG、JPG 或 WebP 用 Base64 嵌入 SVG。
2. 每个状态对应一个独立 SVG。
3. SVG 内部使用 CSS `@keyframes` 播放动画。
4. 每个角色首次制作时建立并保存自己的 `base.svg`，之后所有动作必须复用同一个基础角色结构。
5. 建议统一使用 `viewBox="0 0 256 256"`，同一角色所有状态的画布、中心点、比例和基准线必须一致。
6. 循环动作使用 8 个明确关键姿态；一次性动作使用 6～12 个关键姿态。
7. 透明背景，不得出现场景、文字、编号、边框、水印或运动模糊。
8. 角色及其配饰必须完整，不得裁切。
9. 缩小至 64～128px 的桌宠尺寸后，动作仍必须清晰可辨。
10. 默认朝向右侧，向左移动由网页端使用镜像翻转实现。
11. 阴影必须是独立图层。
12. SVG 至少使用以下稳定图层 ID；没有某种身体部位时可以省略：

* `eyes-js`
* `pupils-js`
* `body-js`
* `head-js`
* `arms-js`
* `accessory-js`
* `effect-js`
* `shadow-js`

13. `idle` 必须预留鼠标追踪能力：

* 眼睛最大偏移 3px。
* 身体向鼠标方向轻微倾斜。
* 阴影向反方向移动并轻微拉伸。
* 鼠标停止后平滑回到中心。
* 鼠标位置由网页 JavaScript 写入 CSS 自定义变量；不要声称纯 CSS 可以读取鼠标坐标。

## 【单个动作的输出结构】

每次收到“角色名称 + 动作名称”后，只生成：

* `output/<character>/base.svg`：仅当尚不存在时建立
* `output/<character>/<action>.svg`
* `output/<character>/<action>.json`
* `preview/<character>-<action>.html`

JSON 中记录：

* `character`
* `action`
* `keyframeCount`
* `keyframes`
* `durationMs`
* `loop`
* `easing`
* `layers`
* `pointerTrackingLayers`
* `seamStrategy`

预览页需要：

* 展示透明背景和深浅两种检查背景。
* 可以暂停、播放和重新开始。
* 可以切换 64px、96px、128px 三种显示尺寸。
* 循环动作至少观察三个完整循环。
* `idle` 页面必须实际验证鼠标追踪。
* 浏览器控制台不得出现 SVG、CSS 或 JavaScript 错误。

完成单个动作后，在回复中说明：

1. 关键帧数量。
2. 每个关键帧的变化。
3. 推荐总时长。
4. 是否循环。
5. CSS easing。
6. SVG 图层。
7. 鼠标追踪图层。
8. 首尾衔接方式。
9. 实际创建或修改的文件。
10. 已执行的验证结果。

初始化阶段只创建规则和目录，不创建任何 `base.svg` 或动作 SVG。完成初始化后，报告找到的 6 张参考图片及对应角色，然后等待我输入“角色名称 + 动作名称”。
